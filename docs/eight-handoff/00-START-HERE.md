# Nth Desktop Eight - Read First

This is the research and implementation handoff for the next Nth Desktop project. The completed Ten app is the reusable foundation; **Eight has not been built in this chat**.

## Recommended target

Original Windows 8 from 2012, before 8.1. The package separates researched historical behavior from proposed Android adaptations. This interpretation can be changed if the owner chooses an 8.1 profile.

## Reading order

1. Nth-Desktop-Eight-Handoff.md - project brief, pinned base and non-regression requirements.
2. RESEARCH-WINDOWS-8.md - appearance, behavior, release boundaries and input model.
3. ENGINEERING-PLAN.md - source map, architecture and implementation phases.
4. ACCEPTANCE-CHECKLIST.md - concrete checks for the next build.
5. DECISIONS.md - default choices and genuinely pending inputs.
6. SOURCES.md - primary-source bibliography, versions and access notes.
7. references/index.html - offline gallery of the included UI images and diagrams.
8. Nth-Desktop-Eight-Visual-Brief.pdf - illustrated overview for quick review.
9. NEXT-CHAT-PROMPT.md - paste into the next project chat.

The new repository URL is pending. No new repository, APK or runtime implementation is included. No source checkout or signing material is bundled: fork the pinned Ten repository.

## Reference integrity

The image gallery uses Microsoft-published UI images, extracted figures and tightly bounded PDF captures. They are not screenshots of an Eight prototype or an independently running Windows VM. Gesture illustrations are labeled as illustrations. The archive does not reproduce complete books, articles or training PDFs.

Each reference has a source URL, source/page identifier, era label, dimensions and SHA-256 in references/reference-manifest.json. Full-resolution originals accompany the gallery; thumbnails are for navigation. Original Microsoft artwork remains attributed to Microsoft.

TEN-BASELINE.json records the frozen source identity; EIGHT-RECOMMENDED-DEFAULTS.json is a machine-readable design proposal, not application code.

The manifest and CHECKSUMS.sha256 allow the next agent to verify extracted files. Open the HTML gallery from its extracted folder, not from inside a ZIP viewer that blocks relative images.
